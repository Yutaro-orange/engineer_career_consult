# Implementation Plan

- [ ] 1. ドメイン層のリファクタリングと型定義拡張
- [ ] 1.1 既存のスキル取得関数からAPI通信ロジックを分離し、型定義のみのモジュールに変換する
  - 既存の`GitHubLanguage`型・`GitHubRepository`型・`GitHubUserRepositories`型を維持しつつ、言語バイト数を含む新しい型構造に拡張する
  - 言語エッジ型（言語名+バイト数のペア）を追加する
  - リポジトリ型に言語接続情報（合計サイズ+言語エッジ配列）を追加する
  - API取得結果を成功・失敗で判別可能な型（リポジトリ配列+成功フラグ）を追加する
  - API通信関数（トークン復号・fetch呼び出し）をこのファイルから除去し、型のexportのみにする
  - _Requirements: 4.1, 4.3_

- [ ] 2. Infrastructure層の新設とAPI通信ロジックの移動
- [ ] 2.1 GitHub APIクライアントモジュールを新設し、トークン復号とGraphQLクエリ実行を担当させる
  - ドメイン層から除去したAPI通信ロジック（トークン復号・fetch呼び出し）を新しいInfrastructure層モジュールに移動する
  - GraphQLクエリを拡張し、Publicリポジトリのみを対象とする`privacy: PUBLIC`フィルタを追加する
  - 言語データを最大20件取得するようクエリを拡張し、各言語のバイト数と合計サイズを含める
  - fetchオプションに`next: { revalidate: 3600 }`を設定し、1時間のキャッシュ再検証を有効にする
  - 返却値をドメイン層で定義した取得結果型に変換し、成功・失敗・0件を呼び出し側が判別できるようにする
  - トークン未設定時・API応答エラー時は成功フラグをfalseにし、空のリポジトリ配列を返す
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, NFR-1, NFR-3, NFR-4, NFR-7_

- [ ] 2.2 アプリケーション層のユースケースが新しいInfrastructure層を参照するよう接続を更新する
  - 既存のユースケース関数のimportをドメイン層のAPI関数からInfrastructure層のクライアント関数に変更する
  - 既存の動作（リポジトリ一覧の取得と変換）が変更後も維持されることを確認する
  - _Requirements: 4.1_

- [ ] 3. 言語集計ロジックの実装
- [ ] 3.1 (P) 単一リポジトリの言語割合を計算する集計関数を実装する
  - 言語エッジ配列と合計バイト数を受け取り、各言語の割合を計算する
  - 四捨五入前の割合が1%未満の言語を「その他」として1つにまとめ、バイト数を合算する
  - 表示用パーセンテージは小数点第1位を四捨五入して整数にする
  - 結果を使用割合の降順でソートする
  - 合計バイト数が0の場合は空配列を返す
  - _Requirements: 1.3, 1.4, 2.3_

- [ ] 3.2 (P) 全リポジトリを横断した言語バイト数を合算する集計関数を実装する
  - 全リポジトリの言語エッジから同一言語名のバイト数を合算する
  - 合算後のデータに対して単一リポジトリ用の集計関数を適用し、割合計算・1%未満集約を行う
  - 結果を使用割合の降順でソートする
  - _Requirements: 2.1, 2.3, 2.4_

- [ ] 3.3 (P) 最大の強み言語を特定する関数を実装する
  - 全体集計の言語割合リストから最もパーセンテージが高い言語を返す
  - 複数の言語が同率で最大の場合、言語名のUnicodeコードポイント昇順で先頭の言語を選択する
  - 言語データが存在しない場合はnullを返す
  - _Requirements: 3.1, 3.2_

- [ ] 3.4 ユースケース関数を拡張し、集計結果を含むページデータを返却するようにする
  - Infrastructure層からリポジトリデータを取得後、各リポジトリに対して言語割合の集計を適用する
  - 全リポジトリ横断の言語集計を実行する
  - 最大の強み言語を特定する
  - 成功フラグ・リポジトリ別データ・全体集計・強み言語をまとめたページデータ型で返却する
  - _Requirements: 1.1, 1.3, 1.4, 2.1, 2.3, 2.4, 3.1, 3.2_

- [ ] 4. SVG円グラフコンポーネントの実装
- [ ] 4.1 (P) SVGドーナツチャートを描画する汎用コンポーネントを作成する
  - 言語割合データ・サイズ・太さをプロパティとして受け取る
  - SVGの`circle`要素と`stroke-dasharray`/`stroke-dashoffset`を使って各言語セグメントを描画する
  - 主要なプログラミング言語に対応した固定カラーパレットを定義する（TypeScript, Python, JavaScript等）
  - `role="img"`と`aria-label`属性で円グラフ全体の説明を付与する
  - Server Componentとして実装する（`"use client"`不要）
  - _Requirements: 1.2, 2.2, NFR-5, NFR-8_

- [ ] 5. プレゼンテーション層のUIコンポーネント実装
- [ ] 5.1 最大の強み言語をバナー形式で表示するコンポーネントを作成する
  - 「あなたの最大の強みは〇〇です」のフォーマットで言語名を目立つスタイルで表示する
  - 強み言語がnullの場合は何もレンダリングしない
  - Tailwind CSSで背景色・フォントサイズを強調したバナーデザインにする
  - _Requirements: 3.1, 3.3, 3.4_

- [ ] 5.2 全リポジトリ横断の言語割合セクションコンポーネントを作成する
  - 円グラフコンポーネントに全体集計データを渡して表示する
  - 言語名とパーセンテージの凡例リストを降順で併記する
  - 凡例リストにはスクリーンリーダーで読み取り可能なテキストを含める
  - _Requirements: 2.1, 2.2, 2.4, NFR-8_

- [ ] 5.3 リポジトリカードコンポーネントを作成する
  - 既存のリポジトリ表示内容（名前・説明・リンク・主要言語）を維持する
  - 言語データが存在するリポジトリには円グラフと凡例を表示する
  - 言語データが空のリポジトリでは円グラフセクションを非表示にする
  - _Requirements: 1.1, 1.2, 1.5_

- [ ] 6. スキルページの統合とレイアウト構成
- [ ] 6.1 スキルページを拡張し、全コンポーネントを統合したレイアウトを構成する
  - ユースケースから取得したページデータをもとに各コンポーネントを配置する
  - レイアウト順序: 強み言語バナー → 全体言語割合セクション → リポジトリ一覧（カード形式）
  - API取得失敗時は既存のエラーメッセージ「スキル情報を取得できませんでした。」を表示する
  - API取得成功・リポジトリ0件時は「リポジトリが見つかりません」を表示する
  - 言語データが一切ない場合は強み言語バナーと全体言語割合セクションを非表示にする
  - _Requirements: 2.5, 3.3, 4.6, NFR-2_

- [ ] 6.2 ローディング画面を作成し、データ取得中にスピナーを表示する
  - Next.jsのSuspense境界に対応したローディングコンポーネントを配置する
  - _Requirements: NFR-6_

- [ ] 7. テスト実装
- [ ] 7.1 (P) 集計ロジックのユニットテストを作成する
  - 単一リポジトリの言語割合計算: 正常ケース、1%未満集約、空配列、全言語1%未満
  - 全リポジトリ横断の合算: 複数リポジトリでの同一言語合算、降順ソート
  - 最大の強み言語: 通常の最大値、同率時Unicode昇順選択、データなし時のnull返却
  - パーセンテージ合計が100になること（四捨五入誤差の許容範囲確認）
  - _Requirements: 1.3, 1.4, 2.1, 2.3, 2.4, 3.1, 3.2_

- [ ] 7.2 ビルド検証を実施する
